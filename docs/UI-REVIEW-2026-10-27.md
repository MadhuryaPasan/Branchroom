# Interface review — 27 October 2026

## Scope and direction

Branchroom is a native desktop Git workspace. This pass reviewed the shared shell and the History, Changes, Snapshots, Branch map, Merge, Compare & recovery, Stashes, Conflicts, Repositories, GitHub, Command center and Settings screens. The design favors compact, consistent controls, readable repository data, visible selection and focus, and progressive disclosure of technical details. Existing Git operations and workflows remain in place.

## Findings and changes

1. **History geometry:** Fixed misaligned and unadjustable columns. The graph, commit, author and date columns now share header/row geometry, support pointer resizing and horizontal scrolling, and have named numeric width controls and a reset. Graph width can accommodate more lanes. The author moves to the row's accessible name and inspector at narrow widths.
2. **Tree navigation:** Added adjustable source columns to branch and snapshot trees, with keyboard-operable numeric alternatives and saved preferences. At high zoom the branch map groups sync controls to leave room for content.
3. **Repository and branch selection:** Reorganized picker rows around the current item and local/remote status. The repository picker keeps path entry accessible; symbolic remote HEAD references are no longer shown as branches.
4. **Commit and snapshot inspection:** Moved common review and IDE actions ahead of expandable technical metadata. Existing destructive and recovery actions remain available.
5. **Layout and polish:** Unified panel treatment, margins, navigation feedback and welcome actions. The sidebar is adjustable. Custom tree nodes now expose hover and focus outlines.
6. **Accessibility and writing:** Added accessible names to width inputs and clearer labels, retained keyboard-accessible width controls, and reviewed layout at 200% zoom. Automated contrast checks cover the defined palette; this is not a WCAG conformance audit.

## Design references

The treatment of tables and adjustable content is informed by [Carbon's data-table accessibility guidance](https://carbondesignsystem.com/building-blocks/core/components/data-table/accessibility/) and [Primer's data-table guidance](https://primer.style/product/components/data-table/guidelines/). Zoom and keyboard alternatives follow the intent of [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and [Primer's text resize guidance](https://primer.style/accessibility/design-guidance/text-resize-and-spacing/). Current-branch history follows the familiar scope described in [GitHub Desktop's branch history documentation](https://docs.github.com/en/enterprise-cloud%40latest/desktop/making-changes-in-a-branch/viewing-the-branch-history-in-github-desktop?platform=windows). General usability decisions were informed by [Nielsen Norman Group](https://www.nngroup.com/articles/usability-101-introduction-to-usability/) and [Microsoft's UI/UX principles](https://learn.microsoft.com/en-us/dynamics365/guidance/develop/ui-ux-design-principles).

## Verification and limits

The automated UI harness uses preview data and disposable repositories. It exercises tree resizing, width controls, pickers, commit details, compact branch layout and other existing workflows; the rendering harness captures all twelve screens at normal size and 200% zoom plus picker, history and Changes states. Captures are generated under `target/qa/redesign`. Personal repositories were not used for testing or modified.

These checks do not replace a native screen-reader audit, live GitHub authentication/network tests, manual verification of every modal and workflow, or signed-release testing. The desktop application has a minimum window size; mobile layouts are not a supported or verified target. Existing release-candidate limitations remain documented in the production audit and parity matrix. A production-readiness or WCAG AA certification is not implied.
